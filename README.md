# Task-08.25 — внедрение зависимостей в Unity

Тестовое задание на C#: переход от глобального `Player.Instance` к Dependency Injection через Zenject. Пример показывает создание игрока с общими данными о здоровье, навыках и экипировке и изменение этих данных из отдельного компонента сцены.

**Unity:** 2022.3.9f1 · **DI:** Zenject · **Сцена:** [SampleScene](Assets/Scenes/SampleScene.unity)

## Демонстрация

Результат примера выводится в Unity Console. При создании игрока выводятся никнейм `John` и здоровье `100`; затем компонент `Main` уменьшает здоровье до `98` и увеличивает число патронов винтовки с `50` до `52`.

## Условие задания

Переделать пример инициализации игрока с синглтона на Dependency Injection, объяснить изменения и продемонстрировать использование нового кода. [Полный исходный текст и пример с синглтоном](docs/TASK.md).

| Область | Требование |
| --- | --- |
| Внедрение зависимостей | Создать интерфейс игрока, зарегистрировать реализацию в IoC-контейнере и получать её в другом коде. |
| Данные игрока | Сохранить здоровье, жизни, никнейм и таблицу навыков; обеспечить изменение данных из разных частей программы. |
| Экипировка | Добавить винтовку с патронами, парашют и ракетный ранец; задавать параметры предметов в рантайме через DI. |
| Единственность экземпляра | Предотвратить создание нескольких экземпляров игрока и обеспечить единство его данных. |
| Качество решения | Соблюсти SOLID, добавить поясняющие комментарии и пример использования в Main. |

## Реализация

[Установщик сцены](Assets/Scripts/Other/PlayerSceneInstaller.cs) регистрирует `IPlayer` как `Player` и подготавливает его зависимости: здоровье `100`, три жизни, навыки `Skill1`–`Skill3` и экипировку. В неё входят винтовка с 50 патронами, один парашют и ракетный ранец с тремя зарядами. Никнейм `John` передаётся отдельным аргументом регистрации.

Zenject передаёт здоровье, экипировку и навыки в конструктор игрока через интерфейсы. [Компонент Main](Assets/Scripts/Other/Main.cs) получает `IPlayer` через поле с атрибутом `[Inject]` и меняет здоровье и число патронов через полученные объекты. Статического доступа `Player.Instance` в реализации нет.

Начальные значения задаются кодом установщика при создании зависимостей. Готовые объекты регистрируются в контейнере и передаются игроку; отдельного механизма настройки параметров предметов во время игры нет. После создания здоровье, жизни, навыки и количество предметов доступны для изменения через свойства.

## Технические решения

| Решение | Применение |
| --- | --- |
| Точка сборки зависимостей | `PlayerSceneInstaller` подключён к `SceneContext`; создание и регистрация зависимостей сосредоточены в установщике. |
| Внедрение через конструктор | `Player` получает `IHealth`, `IEquipment` и `ISkills`, что позволяет подставлять другие реализации. Сам игрок использует Unity `Debug.Log` для вывода начальных данных. |
| Внедрение в компонент сцены | Zenject заполняет поле `IPlayer` в `Main` до вызова `Start`. Компоненту не нужно обращаться к контейнеру напрямую. |
| Время жизни игрока | `AsSingle()` даёт один экземпляр для регистрации в контейнере сцены. `Player` объявлен `sealed`, его конструктор закрыт; глобальная единственность между независимыми контейнерами не обеспечивается. |
| Хранение экипировки | Словарь хранит предметы по имени. Общее свойство `Count` используется для патронов, количества парашютов и зарядов ранца. |
